# 移除任务参与人模型设计

## 1. 决策摘要

Muyu 任务模型不再包含“参与人”概念。任务只保留一个任务负责人 `current_handler_id`。同一 Workspace 的两位成员都可以读取全部未删除任务；负责人可以直接修改，另一位成员修改受保护字段时继续通过既有单人审批请求确认。

项目处于开发阶段，允许清理旧任务关联数据和客户端缓存，不保留 `assignee_ids` 兼容层。

## 2. 目标与非目标

目标：

- 从数据库、FastAPI、Flutter、TypeScript 和同步契约中移除参与人字段与关联表；
- 保留 `current_handler_id` 作为唯一负责人；
- 保留双人 Workspace 的读取、负责人权限和审批边界；
- 用户概览统计所有任务记录，包括一级任务和子任务；
- 通过一次数据库迁移清理旧关联表和旧缓存。

非目标：

- 不增加 `owner_user_id` 或其他任务归属字段；
- 不增加管理员、群组、角色层级或多人审批；
- 不改变任务状态、评论、延期、阻塞、设备验证和 Web 会话模型；
- 不为旧 Android/Web 客户端保留旧字段响应。

## 3. 任务领域模型

任务继续使用现有 Task 表和 UUID 主键，保留标题、描述、状态、时间、延期、阻塞、评论审计、版本和 `parent_task_id` 等字段。删除：

- `assignee_ids` API 和同步字段；
- `TaskAssignee` ORM 模型；
- `task_assignees` 数据表；
- 所有参与人字段版本和参与人集合校验。

`current_handler_id` 是唯一负责人：

- 必须是同一 Workspace 的 ACTIVE 成员；
- 创建任务时默认为创建者；
- 负责人转交继续使用现有字段版本和审批流程；
- `resume_handler_id` 只校验为 Workspace ACTIVE 成员，不再校验参与人集合。

子任务仍是普通 Task，通过 `parent_task_id` 关联，和父任务使用相同负责人规则。

## 4. 读取、写入与审批

同一 Workspace 的两位成员可以读取全部任务，不再按参与人过滤。

“我的任务”改为唯一条件：

```text
task.current_handler_id == current_user_id
```

任务负责人可以直接修改；另一位成员的修改仍创建发给当前负责人的审批请求。删除 `ASSIGNEE_UPDATE` 审批类型及其服务、路由、序列化和测试分支。保留标题、描述、截止时间、状态、进度、四象限、标签、负责人转交和评论删除审批。

阻塞恢复时，`resume_handler_id` 必须是同一 Workspace 的 ACTIVE 成员；恢复后继续切换 `current_handler_id`、写负责人历史和活动记录。

## 5. API 与同步契约

任务创建、更新、详情、快照、增量变更和审批建议不再出现 `assignee_ids`。现有严格请求模型会拒绝旧客户端提交该字段并返回稳定 `422`；旧客户端不在兼容目标内。

任务创建仍由服务端把创建者设为负责人。所有 Workspace 成员可读取任务，写权限仍由负责人和设备状态决定。

## 6. 用户概览

“我的”页使用紧凑概览，不做统计大屏。当前用户概览统计所有未删除且 `current_handler_id` 为当前用户的 Task 记录，父任务和子任务分别计数：

- 全部任务数；
- 未完成数；
- 已完成数；
- `delay_count` 总次数；
- `total_delay_minutes` 总时长，转换为天、小时、分钟。

对方头像显示另一位 Workspace 成员作为负责人时的相同概览。统计从现有 Workspace snapshot 派生，不新增 analytics 表、统计缓存或统计 API。快照刷新后概览更新，刷新失败时保留上一次结果。

## 7. 客户端调整

Android：删除 `TaskItem.assigneeIds`、参与人选择器和相关请求字段；任务详情只保留负责人；清单“我的任务”只按 `currentHandlerId` 筛选；“我的”页显示当前用户概览并支持点击对方头像查看对方概览。

Web：删除 TypeScript `assignee_ids` 类型、筛选、详情展示和编辑逻辑；保留负责人展示、转交和审批。

## 8. 数据库迁移与缓存

新增 Alembic 迁移：

1. 删除 `task_assignees` 表及约束、索引；
2. 保留 Task、负责人、评论、延期、阻塞、活动和审批历史；
3. 不修改已有 `tasks.current_handler_id`；
4. 对负责人为空或不属于 Workspace 的历史任务执行迁移检查，开发环境允许清理，不能静默改写负责人；
5. 客户端递增快照缓存版本或清空旧快照，重新拉取新契约。

## 9. 验收标准

- 新 API 不接受、不返回 `assignee_ids`；
- 数据库不存在 `task_assignees`；
- 两位成员都能读取全部任务和子任务；
- “我的任务”只匹配当前负责人；
- 负责人直改、另一成员审批、负责人转交和阻塞恢复继续成立；
- `ASSIGNEE_UPDATE` 不能创建或审批；
- Android/Web 不再显示参与人控件；
- 用户概览包含父任务和子任务，并正确汇总延期；
- 现有任务、评论、延期、设备授权和 Web 登录测试继续通过。

## 10. 实施顺序

1. 先写后端、Flutter、Web 的失败测试；
2. 删除后端 ORM、服务、路由、审批和快照中的参与人逻辑；
3. 添加 Alembic 迁移并验证负责人数据；
4. 删除 Flutter/TypeScript 模型、筛选和表单逻辑；
5. 接入 Android 用户概览与对方头像入口；
6. 更新当前有效文档，历史文档保留并标注本设计已取代旧参与人模型；
7. 运行全量测试、构建 commit 命名 APK，再进入发布流程。
