# Android 任务导航与多标签设计规格

> **历史文档：已被单分类任务模型替代。** 当前规则见
> [2026-09-04 单分类任务模型设计](./2026-09-04-single-task-classification-design.md)。
> 本文中的多标签数量、自由标签输入和可选标签规则不得用于新实现。

## 1. 状态与范围

本规格定义 Android 客户端任务工作区的底部导航、任务视图和多标签分类能力。它基于当前云端协调架构、双人 Workspace、任务负责人审批和 PostgreSQL 事实源设计，不改变现有认证、设备授权、Web 扫码登录或同步协议的总体方向。

本次范围包括：

- Android 底部四项导航：清单、四象限、日程、我的；
- 从 Android 工作区移除看板入口和看板页面；
- 将四象限改为任务必填字段；
- 为任务增加多个可选分类标签；
- 让标签在任务创建、详情编辑、快照和增量同步中保持一致；
- 为新增行为补充后端、Flutter 和同步测试。

本次不包括：

- 新增独立标签管理页、标签颜色、标签层级、标签权限或标签统计；
- 把标签变成负责人、状态、审批人或访问控制字段；
- 修改 Web 的页面布局；Web 只接收兼容的任务字段并保留现有展示能力；
- 恢复 Android 看板、离线写入、P2P 或新的外部基础设施；
- 增加第三位 Workspace 成员或管理员审批模型。

开发阶段允许丢弃旧任务数据。若数据库中存在历史 `quadrant IS NULL` 的任务，部署前应按新空数据库策略重置数据，禁止静默把旧任务自动归入某个象限。

## 2. 产品模型

### 2.1 Android 底部导航

Android 工作区使用 Material 3 `NavigationBar`，固定四个 destination：

| destination | 目的 | 数据来源 |
| --- | --- | --- |
| 清单 | 按生命周期快速处理任务 | `Task.status` |
| 四象限 | 按重要性/紧急性查看任务 | `Task.quadrant` |
| 日程 | 按截止日期安排任务 | `Task.dueAt` |
| 我的 | 账户、设备和设置 | 当前会话与设备 API |

底部导航只切换当前工作区内容，不重新创建同步控制器。切换 destination 不应丢失快照、滚动状态以外的同步状态或待处理错误。

顶栏继续提供刷新、任务审批入口和扫码登录 Web 入口；标题根据当前 destination 显示“清单”“四象限”“日程”或“我的”。未验证设备仍可查看四个页面，但所有写入控件必须禁用。

### 2.2 清单视图

清单页面保留新建任务入口和任务详情入口，任务按三个固定分组展示：

- 未开始：`TODO`；
- 进行中：`IN_PROGRESS`、`WAITING`；等待中的任务显示阻塞原因；
- 已完成/已失败：`DONE`、`CANCELLED`。当前协议没有独立 `FAILED` 状态，因此 `CANCELLED` 在客户端文案中归入终态分组，不新增状态枚举。

清单页面可以使用标签筛选。筛选仅影响当前列表，不改变服务端任务或任务状态。任务行显示任务编号、标题、状态、标签、象限和截止日期的紧凑摘要。

### 2.3 四象限视图

四象限页面只展示四个固定分组，不提供“未设置”分组：

- Q1：重要且紧急；
- Q2：重要不紧急；
- Q3：不重要但紧急；
- Q4：不重要不紧急。

每个任务必须属于其中一个象限。四象限页面可复用清单的任务卡片、标签筛选和详情跳转，但不允许通过页面操作清空象限。

### 2.4 日程视图

日程页面按 `dueAt` 的本地日期升序分组；同一天内按截止时间和更新时间排序。没有截止日期的任务放入“未安排”，而不是四象限的未设置分组。任务可点击进入既有详情页，日程页面不引入新的日历依赖或重复任务模型。

### 2.5 我的视图

我的页面复用现有 `MyProfileScreen`：显示账户信息、当前用户的 Android 设备列表、设备状态、刷新和撤销其他设备。当前设备不可在本机删除。扫码登录 Web 和任务审批仍从顶栏进入，避免把短期 Web 会话误列为长期 Android 设备。

## 3. 任务数据契约

### 3.1 必填四象限

`Task.quadrant` 改为非空枚举值 `Q1 | Q2 | Q3 | Q4`。

- `POST /api/v1/tasks` 必须携带 `quadrant`；缺失或 `null` 返回 `422 invalid_request`；
- `PATCH /api/v1/tasks/{task_id}` 允许更新 `quadrant`，但不允许把它设置为 `null`；
- 数据库 `tasks.quadrant` 使用 `NOT NULL` 约束；
- 创建任务时不提供默认象限，用户必须明确选择；
- 快照、增量变更、Android 模型和 Web 类型均将象限视为非空值。

### 3.2 多标签

任务增加 `labels: string[]`，默认空数组。标签是分类信息，不是独立领域实体。

服务端规范化规则：

- 每个标签去除首尾空格；
- 空字符串无效；
- 同一任务内大小写不敏感去重，保留第一次出现的显示文本；
- 单个标签最长 32 个 Unicode 字符；
- 每个任务最多 10 个标签；
- 标签总字符数最多 320；
- 超出规则返回 `422 invalid_request`；
- 标签按客户端提交顺序保存，读取时保持该顺序。

PostgreSQL 首版在 `tasks.labels` 保存 JSONB 数组，列为 `NOT NULL`，默认 `[]`，并增加数组类型检查。由于标签数量小且只用于任务分类，不建立 `labels` 表、任务标签关联表或全局词典。

### 3.3 创建、编辑与审批

新建任务请求必须同时提供 `title` 和 `quadrant`，`labels` 可省略，省略等同于空数组。任务详情编辑可以修改标签集合。

任务负责人可以直接修改标签和四象限。另一位 Workspace 成员修改标签或四象限时，沿用现有 `TaskApprovalRequest`：请求只由另一位成员审批，审批前任务保持原值。标签修改属于普通 `TASK_UPDATE` 审批，不新增审批类型；如果修改只包含四象限，继续使用现有 `QUADRANT_UPDATE`。

审批应用前重新检查字段版本和任务负责人，过期请求进入 `CONFLICTED`，不能部分应用标签集合。

## 4. API、同步与客户端边界

所有任务 JSON（列表、详情、快照、cursor change、审批结果）都包含：

```json
{
  "quadrant": "Q2",
  "labels": ["工作", "党员"]
}
```

字段名保持 snake_case；Flutter 使用 `quadrant` 和 `labels`，Web 类型使用 `quadrant` 和 `labels`。同步控制器按完整任务资源替换本地任务，不能只更新标签而遗漏版本、审批或软删除信息。

标签筛选、状态分组、象限分组和日程分组均为客户端派生视图，不新增服务端列表接口。客户端仅使用已同步的任务集合，不能根据筛选结果推断权限。

Web 不改变现有页面布局，但必须能解析并保留 `labels` 和非空 `quadrant`，任务详情保存时把标签作为普通任务字段发送。这样 Android 与 Web 共享同一字段版本和审批语义。

## 5. 错误与兼容行为

- 未选象限创建任务：`422 invalid_request`，明确提示必须选择四象限；
- 清空象限：`422 invalid_request`；
- 非法标签：`422 invalid_request`，错误中指出长度、数量或空标签原因；
- 未验证设备：沿用 `403 device_not_verified`；
- 非负责人修改标签/象限：返回 `202` 和待审批请求，不直接返回已修改任务；
- 任务删除、负责人转移或冲突解决时，沿用现有审批请求失效规则；
- 无截止日期任务只进入日程“未安排”，不影响任务创建；
- 服务器返回未知象限或非数组标签视为协议错误，客户端显示同步失败并保留上一份有效快照。

## 6. 测试验收标准

后端必须覆盖：数据库非空约束、创建/更新标签规范化、标签字段版本、非负责人审批、审批冲突、快照和增量字段；Flutter 必须覆盖底部导航切换、状态分组、四象限四组、日程日期分组、标签筛选、必选象限创建和只读设备；Web 必须覆盖任务 JSON 解析、标签编辑提交和未知/非法字段处理。

在施工完成后，以下命令必须通过：

```bash
make backend-test
make client-test
cd web && npm run typecheck && npm test -- --run && npm run build
make boundary-check
make check-deployment
```

本规格不授权开始工程施工；施工必须按照配套实施计划逐项执行并在每个任务完成后验证。
