### 1. 事项导航与阅读体验

目标：先完成统一任务入口和历史可查，不接入假账目/假打卡数据。

施工范围：

- Android 将一级导航从 `清单 / 四象限 / 日程 / 我的` 重构为 `事项 / 记账 / 打卡 / 我的`。记账和打卡在各自领域未完成前显示真实的未实现状态，不读取任务表或静态示例；完成对应领域后再替换为正式页面。
- `事项` 默认 `此刻`，清单、四象限、日程由标题整行的菜单切换；删除独立常驻视图栏、一级品牌宣传区和重复账号入口。保留审批、设备和资料在“我的”。
- 以 `TaskViewState` 保存三种视图的滚动/筛选/月份/日期状态；离开事项 Tab 后回来不重置；返回键先关闭标题菜单或键盘。
- 统一 Home 计数/分页的交接与验收谓词，分类/字段审批保留审批中心；补充自然周时区兼容测试。完善此刻三个指标、互斥三段和空/错误/stale 状态；任务卡显示状态文字、负责人、分类、截止、阻塞事实或下一步，不放直接完成复选框。
- 增加全部事情的搜索、状态/历史/待接棒过滤和稳定 keyset 分页；详情返回恢复来源筛选和任务 ID 锚点。
- Web 添加等价的事项/记账/打卡/我的主导航和路由别名；旧 `/today`、`/tasks`、审批、动态和任务深链保持解析兼容，账本/打卡页面只在正式 API 可用后开放真实写入。

先写测试：

- Flutter：四 Tab 顺序、事项标题菜单键盘/返回/外部点击、视图状态独立保存、320/360/393/412 边界、stale 保留、三段 ID 互斥和来源恢复。
- Web：主导航路由、旧路由别名、任务详情来源返回、canonical Home-only 数据、筛选/搜索/分页状态和窄视口可访问名称。
- 后端：任务查询字段覆盖、状态过滤、待接棒派生过滤、软删除/历史边界、分页 cursor 绑定和权限测试。

完成门槛：Android/Web/API 使用同一任务源；没有重复任务或客户端伪造的账目/打卡；专项测试通过并更新状态文档。

### 2. 明确下一步正式契约

目标：把用户填写的“下一步”与现有 viewer-aware `next_step` 行动投影分开持久化。

施工范围：

- Alembic 增加可空 `tasks.next_step_text`；现有任务不补造事实，新 snapshot/changes 增量返回 `null`。
- Pydantic、TaskService、Repository、Flutter/Web 模型增加 `next_step_text`，trim 后限制 1-90 Unicode code point；服务端拒绝未知/空白/超长值。
- 新 v1 创建/编辑表单要求下一步；普通编辑由当前负责人在允许状态中修改并带 `base_field_versions.next_step_text`。
- 交接请求增加 `proposed_next_step`，待审批期间不改变任务；批准时与负责人、负责人历史、活动、审批结果和 cursor 原子应用；拒绝保留原下一步。
- 实现新 v1 创建映射 IN_PROGRESS；创建给 TA 原子写任务（创建者负责）、交接请求、事件/cursor/幂等，测试重复请求、部分失败回滚、单人不可选 TA。解除阻塞不变 owner，审计旧恢复负责人路径。
- 活动、详情、Home 卡片和旧 snapshot fallback 明确区分当前文本、拟议文本、交接说明、验收内容、退回原因和行动投影。
- 先保留旧写入兼容窗口并记录客户端契约版本；更新 Android/Web 后再收紧所有新建请求必填，禁止直接 PATCH owner/status 绕过审批。

先写测试：

- 迁移空库升级、现有 null 数据、回滚和 snapshot/changes 兼容。
- API/领域层创建、编辑、Unicode 边界、幂等重放、版本冲突、单人起步和无审批人拒绝。
- 双用户交接待审批/接受/拒绝/并发；确认 owner 和 next_step_text 只有接受后一起变化。
- Android/Web 表单失败保留输入，旧 snapshot 缺字段不丢任务，详情同时解析两个 next-step 概念。

完成门槛：没有一个路径把行动投影当成用户事实；双用户 E2E 和 cursor 重放通过。

### 3. 共享记账

目标：交付独立、精确、可同步的共享账本。

施工范围：

- 新增 `ledger` 模块、schema、Repository、领域服务、Alembic 迁移、REST 路由和审计/cursor 资源。
- `LedgerEntry` 使用整数分和固定 `CNY`，分离 `EXPENSE/INCOME`、付款/收款人、记录人、日期、分类、备注、版本和删除事实。
- 提供月份切换、全部/支出/收入筛选、完整月度收支/结余/分类占比/双方付款汇总；明细筛选不改变月汇总。
- 增改使用 request key/expected version；删除二次确认并保留审计。两位 ACTIVE 成员按共享账本权限管理，服务端不能只依赖按钮。
- Android/Web 页面只消费账本 API，不复用任务 Repository、Home 或 localStorage；stale/错误/重复提交遵循共享同步边界。

先写测试：

- 金额解析 12.34/8.50、零/负数/范围、月份边界和分类汇总。
- 双人增改删、版本冲突、幂等重放、并发删除、审计/cursor、重启持久性和迁移回滚。
- Android/Web 筛选不改变汇总、二次确认、窄屏/键盘/无障碍和失败保留输入。

完成门槛：账目不是任务，不走任务验收；干净 PostgreSQL 和已有数据迁移通过。

### 4. 打卡与纪念日

目标：交付个人习惯和共享纪念日，并让准备事项进入既有任务闭环。

施工范围：

- 新增 `checkins` 模块与 `habits`、`habit_checkins` 表，频率只支持每日/每周/每月；周期键使用 Workspace 时区，唯一约束防重复。
- 打卡页保留日常打卡/纪念日，默认我的，支持 TA 的/全部；未开始或暂停不可打卡，删除习惯确认关联记录一起删除且审计保留。
- 只有习惯 owner 能新增、编辑、暂停、恢复、打卡、撤销当前周期和删除；TA 可查看。修改频率保留历史快照，暂停不删除历史。
- 新增 `anniversaries` 模块与公历日期、类型、准备天数、备注、版本和审计；实现 2 月 29 日非闰年按 2 月 28 日、日期差倒计时。
- 纪念日双方可查看编辑并记审计，未来原始日期不提前发生；手动生成者为唯一负责人，初始 IN_PROGRESS，截止本次日期，下一步明确。
- 生成准备事项使用稳定 `anniversary:{id}:{occurrenceDate}` source key，双方并发最多一条；删除纪念日不删除任务，已有任务日期和历史不被静默改写。
- Android/Web 只消费正式领域 API；生成任务使用统一负责人、下一步、交接、阻塞、验收和 cursor 规则。

先写测试：

- 周日/周一、月末/月初、暂停/恢复、修改频率、撤销当前期、重复点击和本人/TA 权限。
- 注入时钟和业务时区测试，覆盖 DST、跨日/周/月、今天/未来/已过日期和 2 月 29 日。
- 双用户并发生成 source key、删除纪念日后任务保留、任务闭环和重启持久性。
- Android/Web 操作失败、stale、无障碍和小屏布局。

完成门槛：辅助领域表、API、迁移、客户端仓储和权限测试同时存在；不以本地存储或假数据验收。

## 规则

- 每个生产行为改动先增加失败测试，确认失败原因后再实现。
- 每个数据库迁移验证空库升级、回滚和现有数据；生产迁移前核对线上 head 与备份。
- 不恢复参与人、多人 Team、共享密码、旧 `WAITING` 新写入、P2P、本地伪同步或任务复制。
- 不把文档勾选、单元测试、模拟身份或没有设备的截图当作真实发布验收。
- 计划复选框只在对应代码、测试和文档证据完成后勾选。
