# Android 客户端视觉方向设计规格

## 1. 状态与范围

本规格固定 Muyu Android 客户端的视觉方向。它与 Web 视觉方向规格保持同一套产品气质和基础设计令牌，但不要求 Android 复刻 Web 的页面布局或导航方式。

Web 视觉基准见：[Web 前端视觉方向设计](./2026-08-31-web-frontend-visual-direction-design.md)。跨端共同的感觉是：

> 安静，但不冷淡；简洁，但不空洞；有生活感，但不幼稚。

Android 的实际设计以手机单手操作、Material 3、系统返回手势、触控可达性和移动网络状态为基础。底部导航、AppBar、全屏页面、底部表单和系统级反馈属于 Android 的平台表达，不需要为了与 Web 一致而改成桌面 Web 结构。

本规格固定：

- Android 的颜色、字体、间距、圆角、表面和状态表达；
- 任务工作区、底部导航和详情页的视觉层级；
- 触控、键盘/输入法、返回和加载状态的表现原则；
- 同步、空状态、审批、冲突和只读设备的统一视觉语言；
- Android 与 Web 之间应保持一致、可以不同和禁止偏离的部分。

本规格不定义新的任务字段、后端 API、同步协议、Android 页面功能范围或具体 Flutter 目录结构。它也不要求立即修改现有 Dart 实现。

## 2. 设计目标

Android 打开后应让用户快速回到正在做的事情，而不是先理解系统结构。页面优先回答：

1. 我现在应该继续哪一件事；
2. 接下来可以做什么；
3. 有没有被等待或审批卡住的事情；
4. 我能否用一次清晰的触控操作记录进展。

Android 是 Web 的行动延伸，不是缩小版后台管理系统。信息需要适合短时间查看和连续操作，但不能通过密集表格、统计卡片或过多颜色制造“效率工具”的压迫感。

## 3. 跨端保持一致的视觉语言

### 3.1 气质与层级

- 使用冷白页面背景、白色主要表面和深绿主色；
- 用浅绿色强调正在推进的唯一重点，用珊瑚色表达临期、等待和审批；
- 页面主要依靠标题、分组、留白和细分隔线建立层级；
- 普通任务保持线性列表，不为每个任务创建浮动大卡片；
- 默认不使用渐变、玻璃拟态、光晕、装饰性插画或大面积彩色背景；
- 颜色不能代替状态文字、图标和明确动作；
- 文案直接、自然，关注下一步行动，不使用“管理中心”“数据概览”等后台措辞。

### 3.2 颜色令牌

Android 使用与 Web 对齐的基线颜色。Flutter 实施时应集中映射到 `ColorScheme` 或应用级主题令牌，业务组件不应自行定义近似色。

| 用途 | 基线值 | Android 用法 |
| --- | --- | --- |
| 页面背景 | `#F8FAF9` | `Scaffold` 背景和页面空白区域 |
| 主表面 | `#FFFFFF` | AppBar、输入区和必要的底部表单 |
| 主文字 | `#1D2D29` | 页面标题和主要任务文字 |
| 正文文字 | `#25312E` | 说明、正文和可读内容 |
| 次级文字 | `#7C8783` | 日期、标签、辅助信息 |
| 品牌主色 | `#225F50` | 主动作、选中态和强调线 |
| 交互绿色 | `#2E7663` | 按下态、进度和当前操作 |
| 浅绿强调 | `#E7F0ED` | 当前重点任务或正向状态 |
| 珊瑚提示 | `#B2573B` | 临期、等待和审批提示 |
| 浅珊瑚背景 | `#F3DFD7` | 等待和温和警示区域 |
| 分隔线 | `#DCE3E0` | 列表行、区块和输入边界 |
| 同步正常 | `#52A083` | 低权重同步状态 |

错误状态使用独立的可访问红色，不能用珊瑚色隐藏错误的严重程度。深色主题暂不属于首版范围，不能在 Android 端单独引入一套未经过验证的夜间视觉。

### 3.3 字体和文字

Android 优先使用系统无衬线字体，默认跟随系统字体缩放和无障碍设置。英文或数字可以使用 `Inter` 或系统回退字体，但不引入装饰字体。

建议层级如下，具体字号应以 Material 3 的可访问性和设备密度校验为准：

| 层级 | 建议字号 / 行高 | 用途 |
| --- | --- | --- |
| 页面标题 | `24px / 32px` | AppBar 标题或页面首标题 |
| 区块标题 | `16px / 24px` | 当前任务、接下来、等待中 |
| 任务标题 | `14px / 20px` | 列表主要内容 |
| 正文 | `14px / 20px` | 描述和确认内容 |
| 辅助信息 | `12px / 16px` | 截止时间、负责人、标签 |

不使用负字距，也不随屏幕宽度连续缩放字号。长标题可以自然换行，不能用裁切、重叠或压缩到无法阅读来维持单行。

### 3.4 Flutter 统一主题令牌落地

安卓端必须在应用级主题中集中定义 Muyu 令牌。业务页面只能通过 `Theme.of(context).colorScheme`、`Theme.of(context).textTheme` 和应用级 `ThemeExtension` 读取颜色、文字与状态样式，不得在页面、组件或列表行中散落新的 `Color(0xff...)`、字号、圆角或阴影值。

`MuyuApp` 使用亮色 Material 3 `ColorScheme`，字段映射固定如下：

| Flutter 令牌 | 值 | 用途 |
| --- | --- | --- |
| `scaffoldBackgroundColor` | `#F8FAF9` | 页面冷白背景 |
| `surface` | `#FFFFFF` | AppBar、输入区、必要浮层 |
| `onSurface` | `#1D2D29` | 标题和主要文字 |
| `onSurfaceVariant` | `#7C8783` | 日期、负责人、标签等辅助文字 |
| `primary` | `#225F50` | 品牌、选中态、主要动作、FAB |
| `onPrimary` | `#FFFFFF` | 深绿表面上的文字和图标 |
| `secondary` | `#2E7663` | 进度、交互绿色和按下态 |
| `outline` | `#DCE3E0` | 分隔线、输入边界和非激活轮廓 |
| `error` | `#A33B2E` | 错误文字和错误图标 |
| `errorContainer` | `#FBEAE7` | 错误背景 |

浅绿重点、珊瑚提示、浅珊瑚等待背景、同步正常色和禁用色属于跨组件状态令牌，放入 `MuyuThemeExtension`（或等价的应用级主题扩展）统一提供：`focusSurface=#E7F0ED`、`coral=#B2573B`、`coralSurface=#F3DFD7`、`sync=#52A083`、`disabled=#A3AFAA`。这些状态色必须同时配合文字或图标，不得只依赖颜色。

间距、圆角和层级使用固定常量：

- 间距只使用 `4 / 8 / 12 / 16 / 24 / 32`，统一由 `MuyuSpacing`（或等价令牌）提供；
- 普通控件圆角 `6px`，面板/浮层最大 `8px`，状态徽标才允许使用全圆角；
- 普通页面区块和任务行 elevation 为 `0`，菜单、对话框和抽屉只允许一层低强度 Material 阴影；
- FAB 使用 `colorScheme.primary`，禁止继续使用旧的蓝色 `#2F80ED` 或其他页面自定义蓝色；
- 文字层级统一从 `TextTheme` 读取：页面标题 `24/32`、区块标题 `16/24`、任务标题 `14/20`、正文 `14/20`、辅助信息 `12/16`，所有文本 `letterSpacing` 保持 `0`。

施工完成后的静态检查必须确认业务页面不再包含旧种子色、蓝色 FAB、散落的近似主题色或超过 `8px` 的通用圆角；新增页面只能引用上述主题令牌。

## 4. Android 页面骨架

### 4.1 应用级结构

Android 继续使用 Material 3 应用结构：

- `AppBar` 承载当前页面标题和少量全局动作；
- `NavigationBar` 承载主要工作区入口；
- 页面内容使用单列滚动布局；
- 编辑和创建优先使用底部表单或独立详情页；
- 次要操作收进菜单、底部操作区或详情页，不在顶栏堆叠图标。

不使用固定深色侧栏，不在手机页面模拟 Web 的顶部一级导航。顶栏操作数量应保持克制，刷新、扫码、审批等动作只有在当前上下文确实有用时才出现。

### 4.1.1 任务系统与“我的”标题边界

清单、四象限和日程属于同一个任务系统，三页必须使用一致的顶部标题容器：相同的 AppBar 高度、背景表面、标题字号与字重、左右内边距、分隔线和页面切换反馈。三页可以保留各自必要的上下文操作，但这些操作只能出现在统一标题容器的动作区域内：清单使用任务分类下拉和更多菜单，四象限使用象限上下文操作，日程使用日期导航或刷新操作。

“我的”是独立的账户、共享关系和设备页面，不要求复用任务系统的标题内容或动作布局。它使用独立的账户页面标题，可在右上角提供审批中心和扫码登录 Web 两个入口；这两个入口不得变成底部导航项，也不得新增第五个 Tab。我的页面的资料、共享空间、用户概览和设备管理内容按账户语义组织，不显示任务系统的分类下拉或任务更多菜单。

### 4.2 底部导航

底部导航保留当前 Android 的四个入口：清单、四象限、日程、我的。它是 Android 原生布局选择，不是对 Web 导航的偏离。

- 选中态使用深绿色图标、文字和 Material 选中指示，不使用高饱和大色块；
- 未选中态使用中性灰绿色，保证图标和文字仍可辨认；
- 导航切换不清空同步快照，不重置全局错误状态；
- 每个入口只表达一个稳定目的，不把临时审批或同步状态增加为第五个入口；
- 页面滚动位置可以保留，但切换入口不能造成内容闪烁或重新请求的视觉跳变。

### 4.3 任务工作区

清单是 Android 默认行动入口。页面顺序保持行动优先：

1. 当前任务或需要继续推进的重点任务；
2. 接下来可以处理的任务；
3. 等待中的任务和阻塞原因；
4. 待处理审批；
5. 快速创建任务。

重点任务最多一个，使用浅绿色区域和左侧深绿强调线。没有重点任务时直接省略该区域，不显示空占位卡片。

普通任务使用稳定高度的列表行或紧凑 Material ListTile，内容建议包含完成控件、标题、必要辅助信息和尾部截止时间/状态。任务行不使用连续的厚重边框和独立阴影。

### 4.4 四象限与日程

四象限、日程是对同一任务集合的不同查看方式，不是三套独立产品。

- 四象限使用清晰的分组标题和适量留白，不把四个分组做成四张装饰性大卡片；
- 日程按日期线性分组，日期是视觉锚点，任务行保持与清单一致；
- 两个页面复用任务行、标签、状态和截止时间的表达方式；
- 分组为空时显示简短解释和下一步动作，不使用大型插画或统计数字填充空间。

### 4.5 任务详情与创建

任务详情是行动页面，不是属性表单。标题、下一步描述、当前状态、负责人和截止时间优先显示；活动记录、审批和其他辅助信息按需展开。

创建任务时优先让用户完成标题、四象限和必要的下一步信息。标签、截止时间和参与人等补充项按自然顺序出现，不在首屏一次铺开所有高级字段。

保存、开始、完成、等待和审批等动作应有清晰的主次层级。详情页不同时显示多个同权重的彩色主按钮。

## 5. 触控与平台交互

- 主要触控目标遵循 Android 可访问尺寸，图标按钮需要足够的点击区域；
- 按下、选中、禁用和处理中状态使用短暂、低幅度的颜色或表面变化；
- 触控反馈不能改变列表行高、文字位置或底部导航尺寸；
- 使用系统返回手势关闭详情、底部表单、菜单和冲突处理页面；
- 表单打开输入法后，提交动作和错误信息仍必须可见，不能被键盘遮挡；
- 删除、拒绝、取消等不可逆或高影响动作使用 Material 3 确认对话框；
- 普通保存成功优先通过内容即时更新确认，不为每一次写入弹出 toast；
- 网络写入显示局部处理中状态，避免整页闪烁或回到列表顶部；
- 尊重系统字体放大、TalkBack 和 `prefers-reduced-motion` 对应的 Android 无障碍设置。

## 6. 状态表达

### 6.1 同步和只读设备

同步正常时只显示低权重的绿色状态点或简短文案。正在刷新使用局部进度指示，不遮住任务内容。

已有快照但同步失败时继续显示内容，并在页面靠近标题的位置说明“内容可能不是最新”。如果设备尚未验证，使用明确的只读提示；查看任务仍可用，所有写入动作必须禁用并说明原因。

认证失效、Workspace 不可用或同步协议错误需要进入对应的处理页面，不能让用户误以为当前内容仍可安全写入。

### 6.2 空状态和错误

空状态使用一句与当前页面相关的解释和一个明确动作，例如“今天没有需要处理的任务”配合“记下一件事”。不使用大型插画、营销式标题或空白卡片。

错误靠近触发位置展示，保留用户已经输入的内容。错误信息需要说明下一步，例如重试、返回、重新登录或查看冲突。

### 6.3 等待、审批和冲突

- 等待显示正在等待的条件和解除阻塞负责人，使用浅珊瑚背景或珊瑚文字；
- 审批说明变更对象、来源和动作，不把审批变成数量统计；
- 冲突使用高优先级警示和明确的解决动作，不能只显示版本号；
- 已完成任务降低文字权重，但保留历史可读性和恢复入口；
- 正常同步、处理中、失败和过期状态不能只依赖颜色区分。

## 7. 与 Web 的关系

### 7.1 必须一致

- 产品气质和文案语气；
- 背景、表面、深绿主色、珊瑚提示色和状态语义；
- 重点任务最多一个的视觉原则；
- 普通任务采用线性行、不使用后台 KPI 和大面积装饰；
- 同步、空状态、审批、等待、冲突和错误的语义；
- 圆角、阴影、动画和图标的克制程度。

### 7.2 可以不同

- Web 使用顶部轻导航，Android 使用底部 `NavigationBar`；
- Web 使用鼠标悬停和键盘焦点，Android 使用触控按下态、系统返回和 TalkBack；
- Web 内容区居中并限制最大宽度，Android 使用单列滚动和设备安全区；
- Web 可使用内联编辑，Android 可使用底部表单或独立详情页；
- Web 通过浏览器会话登录，Android 保持短信登录、设备身份和扫码批准流程。

### 7.3 禁止偏离

Android 后续页面不得因为手机屏幕较小而退回以下模式：

- 黑色后台侧栏或仿桌面控制台；
- 首页统计卡片、任务数量大数字和默认看板；
- 每个任务一个浮动大卡片；
- 过度使用渐变、阴影、圆形装饰或强烈品牌色块；
- 只有颜色没有文字的状态；
- 把同步游标、内部 ID、版本号等技术细节放在普通用户首屏；
- 为追求“移动效率”而缩小触控目标、堆叠顶栏操作或牺牲文字可读性。

## 8. Android 验收标准

视觉实施后必须满足：

1. Android 默认进入清单，并以当前任务、接下来、等待/审批和快速创建为行动主线；
2. 清单、四象限和日程使用一致的任务系统顶部标题；我的使用独立账户标题，但四页共同保留现有底部导航结构，颜色、层级和任务行遵循本规格；
3. 普通任务行高度稳定，按下、加载、徽标和状态变化不会造成布局跳动；
4. Android 主题令牌与 Web 基线颜色保持对应，不在业务组件中散落近似色；
5. 关键文字、图标、焦点/按下态和错误信息在系统字体放大后仍可读、可操作；
6. 小屏 Android 设备上无横向溢出、文字遮挡、键盘遮挡主要动作或底部导航重叠；
7. 同步过期、断网、只读设备、空列表、等待、审批、冲突和认证失效均有稳定的非颜色状态表达；
8. Android 页面与 Web 截图并排检查时保持同一产品气质，同时能看出 Android 的原生触控结构；
9. 不新增深色主题、复杂动效或装饰性插画，除非另行更新视觉规格并确认。

本规格是 Android 后续 UI 设计的约束。若实施中需要改变主色关系、任务层级、底部导航表达或状态语义，必须先更新本规格并重新确认。
