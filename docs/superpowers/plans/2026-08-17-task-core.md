# Phase 2 Task Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the authenticated two-user task workflow across PostgreSQL/FastAPI and Flutter Android/Web.

**Architecture:** Add a focused `task` domain and shared `activity` model to the existing FastAPI monolith. Domain services own validation and atomic history/event writes; routes only translate typed HTTP contracts. Flutter consumes the REST contract through a task repository and presents tasks as the signed-in default workspace.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2.0, Alembic, PostgreSQL/SQLite, pytest, Flutter 3.47/Dart 3.13.

**Spec:** `docs/superpowers/specs/2026-08-17-task-core-design.md`

## Global Constraints

- System has exactly two fixed users and no task-level authorization.
- Store absolute timestamps in UTC and display them in the client local timezone.
- Support only one subtask level; parent and child statuses are independent.
- Every task write atomically appends an immutable activity event.
- Phase 2 does not expose WAITING, delay, conflict, comment, recurring-task, or analytics behavior.
- Implement behavior test-first and verify SQLite, PostgreSQL, Flutter analyze, and Flutter tests.
