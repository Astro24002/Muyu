# Android 与独立 Web 客户端实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** 将 Web 从 Flutter Web 拆分为独立的 TypeScript + Vite SPA，保留 Python 3.12 + FastAPI 作为纯 API/WebSocket 后端，使 Flutter 只构建 Android，并让 tag/release 触发的流水线产出可部署 Web 静态包和 Android 产物。

**Architecture:** web/ 是使用原生 DOM、fetch 和浏览器 Cookie 的 Vite 单页应用；它通过同源 /api 调用现有 FastAPI 协议，通过 Cookie 建立 WebSocket。client/ 删除 Web 分支，只保留 Android 登录、设备签名、扫码批准和任务同步。Caddy 在最终镜像中服务 web/dist 并代理 /api/*，FastAPI 镜像只包含 Python API。

**Tech Stack:** Python 3.12、FastAPI、PostgreSQL、Flutter 3.47 Android、TypeScript、Vite、Vitest、jsdom、原生 DOM、qrcode、Caddy 2.10。

**Spec:** docs/superpowers/specs/2026-08-25-android-web-client-boundary-design.md

## Global Constraints

- 后端开发语言固定为 Python 3.12，FastAPI 只提供 JSON API、WebSocket 和认证协议，不添加模板或页面路由。
- Web 使用 TypeScript + Vite；首版不引入 React/Vue、SSR、第三方 CDN 或浏览器端 Android 私钥。
- Web 请求使用同源 /api 和 credentials: include；browserProof 只保存在内存，二维码 proof 不写入 localStorage、sessionStorage、URL 或日志。
- Flutter 只支持 Android；不得保留 kIsWeb 启动分支、Web 登录页面、Flutter Web 构建命令或 Web device 集成测试。
- PostgreSQL 仍是唯一事实源；Web 不实现离线写入，不创建第二个本地事实源。
- CI 只监听版本 tag v*.*.* 和 release.published；普通分支 push、普通 tag 和 Pull Request 不触发 CI。
- 所有写入沿用现有 request_id 幂等、字段版本和 409 冲突协议；成功提交后才依赖 WebSocket 提示刷新。
- 不把短信 AppCode、OTP pepper、数据库凭据、签名密钥或生产 Cookie 写入仓库、Vite bundle、APK 参数或日志。
- 每个任务遵循 TDD：先写一个能证明目标行为的失败测试，再实现最小改动，运行针对性测试和格式检查后提交。

patchTask(id: string, input: { requestId: string; changes: Record<string, unknown>; baseFieldVersions: Record<string, number> }): Promise<TaskItem & { cursor: number }>;
resolveConflict(taskId: string, conflictId: string, input: { requestId: string; resolution: 'current' | 'proposed' }): Promise<TaskItem & { cursor: number }>;

- [ ] CI has no pull_request trigger, no unfiltered push, no flutter test -d chrome, and no flutter build web.
