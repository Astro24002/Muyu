# Build Artifacts

Local development produces a commit-named Android debug APK:

- `client/build/app/outputs/flutter-apk/Muyu-<short-commit>.apk` (Android debug)

This artifact is intentionally signed with the local Android debug key and is
not a release asset. The internal `app-debug.apk` generated by Flutter is not
the distributable filename.

Version-tag and published-release workflows produce a version-named Android
APK only after the backend, Android, and browser checks pass:

- `client/build/app/outputs/flutter-apk/Muyu-vX.Y.Z.apk` (fixed release key)
- `web/dist`, packaged as `web-release.tar.gz`

The version APK is built by `scripts/build-android-release.sh`. The workflow
requires `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD`; it materializes the keystore
under the runner temporary directory, validates the alias, builds the release
variant, runs `apksigner verify`, and removes the keystore in an always-run
cleanup step. A missing or invalid keystore fails the release. The Gradle
release variant never falls back to the debug key.

The protected release job may also produce `app-release.aab` after the same
signing secrets are present and valid. No keystore or signing password is
committed to the repository.

For each published artifact, generate a checksum and retain the source commit
and version beside it:

```sh
sha256sum app-debug.apk app-release.aab web-release.tar.gz > SHA256SUMS
git rev-parse HEAD > SOURCE_COMMIT
```

The local `client-build` target carries the source commit in the debug APK
filename automatically. Flutter's `app-debug.apk` remains only as an internal
intermediate file:

```sh
ANDROID_BUILD_ENV=production API_BASE_URL=https://muyu.bkverse.space make client-build
# client/build/app/outputs/flutter-apk/Muyu-$(git rev-parse --short HEAD).apk
```

Local development may opt into a LAN or loopback API explicitly:

```sh
ANDROID_BUILD_ENV=local API_BASE_URL=http://10.0.2.2:8080 make client-build
```

Release assets use the version tag instead, for example
`Muyu-v0.1.0.apk`; the release workflow does not rename a debug APK or attach
a commit-named APK to a GitHub Release.

For an explicitly authorized local release build, provide the same fixed
keystore through environment variables and use the separate target:

```sh
API_BASE_URL=https://muyu.bkverse.space \
RELEASE_TAG=v0.1.0 \
ANDROID_KEYSTORE_PATH=/secure/path/muyu-release.jks \
ANDROID_KEYSTORE_PASSWORD='...' \
ANDROID_KEY_ALIAS='...' \
ANDROID_KEY_PASSWORD='...' \
make client-release-build
```

Do not put the keystore, passwords, or this command with real values into the
repository or build logs.

Install the debug APK only on an internal/test device. Supply the API origin at
build time when it is not served from the same origin:

```sh
ANDROID_BUILD_ENV=production API_BASE_URL=https://muyu.bkverse.space make client-build
cd web
npm ci
VITE_API_BASE_URL=/ npm run build
tar -czf web-release.tar.gz -C dist .
```

The Caddy image builds `web/dist` from the checked-in Vite package and serves it
from `/srv`. FastAPI keeps `WEB_ORIGIN` only for server-side origin validation;
it is never passed to the browser bundle.

No iOS artifact is part of this release.
