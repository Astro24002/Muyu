## 1. 目的

本规格记录 v1 产品文档与当前正式工程之间的兼容边界，作为后续 Android、Web、FastAPI、PostgreSQL 和同步施工的共同依据。它不把当前原型的本地数据模型当作生产契约，也不把当前已有功能误记为 v1 已完成。

本阶段继续使用真实手机号、真实 Workspace 和服务端事实源。Workspace 仍最多两名 `ACTIVE` 成员；任务只有一个 `current_handler_id`；所有业务写入继续在同一数据库事务内完成，并带幂等键、期望版本、活动事实和 Workspace cursor。

## 2. 不变量与兼容决策

### 2.1 任务状态

后端、数据库、snapshot 和 changes 继续使用六个内部状态：

```text
TODO / IN_PROGRESS / BLOCKED / REVIEW / DONE / CANCELLED
```

v1 目标展示映射如下；这是待实施映射，不代表客户端已经完成：

| 内部状态 | v1 中文展示 | 说明 |
| --- | --- | --- |
| `TODO` | 进行中（兼容原待进行事实） | 产品归入 ACTIVE；内部仍为 TODO，不等同于待接棒 |
| `IN_PROGRESS` | 进行中 | 当前负责人推进中的任务 |
| `BLOCKED` | 阻塞中 | 必须保留阻塞原因和恢复负责人 |
| `REVIEW` | 待验收 | 负责人已提交，等待另一位成员验收 |
| `DONE` | 已完成 | 另一位成员已通过验收 |
| `CANCELLED` | 已取消 | 历史终态，保留可查和现有重开兼容路径 |

v1 原型中的 `ACTIVE`、`HANDOFF_PENDING` 和 `REVIEW_PENDING` 只作为产品概念或交互上下文，不写入当前数据库枚举。待处理交接由 `HANDLER_TRANSFER` 请求表示，待验收由 `REVIEW` 任务状态加唯一 `STATUS_UPDATE` 请求表示。有效待接棒请求优先展示“待接棒”，但负责人和底层状态不变；`IN_PROGRESS` 归入产品 `ACTIVE`，`REVIEW` 对应 `REVIEW_PENDING`。`CANCELLED` 不属于开放集合，保留历史读取。未经单独迁移设计，不删除 `CANCELLED`、重开和旧 `WAITING` 读取映射。v1 主流程不新增取消、重开、撤回或删除动作。

### 2.2 用户填写的下一步与查看者行动投影分离

当前任务详情里的 `next_step` 是按查看者派生的行动上下文对象，包含 `kind`、`label`、`can_act`、`actions` 和可选 `request_id`。它不是用户填写的文本，不能被持久化字段覆盖。

v1 新增独立的 `next_step_text`：

- 数据库字段为可空 `TEXT`，用于兼容已有任务；新 v1 客户端创建任务时必须发送非空、trim 后 1-90 个 Unicode code point 的文本；服务端是最终校验者，不静默截断。
- snapshot、changes 和任务详情以 `next_step_text` 返回；任务详情同时继续返回现有 viewer-aware `next_step` 对象。
- 现有任务若没有该字段，读取时返回 `null`，详情继续用既有事实投影；客户端显示“尚未记录明确下一步”，不能编造用户事实。
- 新客户端在创建和编辑表单中把下一步作为独立字段；普通编辑只允许当前负责人在允许状态中修改，不允许借此改负责人或状态。
- `HANDLER_TRANSFER` 的 `proposed_changes` 使用 `proposed_next_step`。待审批期间任务的 `next_step_text` 不变；批准时与负责人、负责人历史、审批结果、活动和 cursor 在同一事务内应用；拒绝、撤回或冲突不覆盖原文本。
- 交接说明 `transfer_note` 与 `proposed_next_step` 都属于请求上下文，不把拟议值提前写入任务当前事实。
- 验收提交的 `review_content` 仍是本次交付说明，不等同于 `next_step_text`；退回原因仍写入请求、任务兼容字段和活动 payload。
- 下一步变更进入追加式活动，记录前后值和实际操作者；snapshot 缺少新字段时按旧客户端兼容规则读取。

2026-09-18 实际施工边界：`0015_task_next_step_text`、任务 schema/服务、snapshot/changes、任务查询、Android/Web 模型与创建/编辑表单已经落地；`HANDLER_TRANSFER.proposed_next_step` 已接入服务端审批校验、原子批准和 Android 交接表单；`X-Muyu-Client-Contract` 已接入公共校验、CORS、Android/Web 请求和 v1 创建必填校验；创建给 TA 已接入目标成员、稳定幂等指纹、原子审批请求、最终 cursor 和 Android/Web 表单。旧 API 请求仍可省略下一步；首版 `Asia/Shanghai` 业务周边界已落地，Workspace 可配置时区、完整日期兼容、真实双用户、真机和线上验收仍未完成，因此不能把整体 v1 协作契约称为已交付。

迁移采用两阶段兼容策略：第一阶段增加可空字段并让旧客户端继续读取/写入已有字段；新 Android/Web 请求携带 `X-Muyu-Client-Contract: 2026-09-v1` 后，服务端对创建强制要求 `next_step_text`。该 header 只用于兼容校验，不参与鉴权或权限判断。完成一轮客户端更新和旧写入路径退役后，再收紧为所有新建请求必填。兼容窗口必须在状态文档中保留起止版本和验证证据，不能把兼容缺失值写成 v1 完整能力。

### 2.3 事项导航

目标一级导航固定为：`事项 / 记账 / 打卡 / 我的`。

- `事项` 是统一任务工作区，默认显示 `此刻`；标题整行打开紧凑菜单，选项为 `清单 / 四象限 / 日程`，当前标题为 `此刻⌄ / 四象限⌄ / 日程⌄`。
- 清单、四象限、日程共享同一任务 snapshot、仓储和详情路由；它们的滚动、四象限负责人筛选、日历月份和选中日期只是客户端 `TaskViewState`，不是共享业务数据。
- `全部事情` 是我的下级检索/历史入口，不是新的底部 Tab。它读取同一任务源，默认排除软删除行但包含已完成、已取消历史；事项此刻不显示直接入口。
- `记账` 和 `打卡` 必须等各自正式领域 API/仓储可用后接入真实页面；在此前不得用任务、localStorage 或静态示例数据冒充已实现模块。
- `我的` 保留当前账号、Workspace、审批、设备和资料入口；审批和扫码仍是账号相关操作，不回到事项页顶部。

Android 使用底部四 Tab；Web 使用等价的一级路由/主导航，不要求桌面端机械复制底部栏。旧 Web `today`、`tasks`、`approvals`、`activity` 哈希路由保留解析兼容并逐步映射到事项或二级入口，不能因导航重构丢失深链接和任务详情来源。

### 2.4 此刻投影与指标

只对未完成任务进行三段互斥分组，优先级固定：

```text
BLOCKED -> blocked
否则 current_handler_id == viewer_user_id -> mine
否则 -> other
```

开放集合明确为未删除的 `TODO/IN_PROGRESS/BLOCKED/REVIEW`，兼容的 `CANCELLED` 与 `DONE` 均不进入三段。

`REVIEW` 任务仍按负责人进入 `mine` 或 `other`，不能因为验收人变化而改组。每个任务在同一 Home API 投影最多出现一次；响应继续保留 canonical 分组供兼容消费者使用。

入口指标保持独立口径：

- `needs_me`：有效待接棒或待验收请求的下一棒（`approver_id`）是当前用户；
- `waiting_on_other`：有效待接棒或待验收请求的下一棒是另一位 ACTIVE 成员；
- `due_soon`：未完成、已成立任务的 `due_at` 位于服务端 `as_of` 起 14 天的半开时间窗 `[as_of, as_of + 14 天)`；不包含逾期、DONE、CANCELLED 或软删除任务。新客户端使用 `entry_counts.due_soon`、`entries.due_soon` 和 `/home/entries/due_soon`。
- `due_this_week`：旧客户端兼容字段，继续按服务端返回的当前自然周边界统计，包含本周已逾期但未完成的任务；新客户端不把它当作 `due_soon`。

仅包含 `HANDLER_TRANSFER` 与进入 DONE 的验收请求，不能将所有 `STATUS_UPDATE`、字段修改或分类审批一并计入。当前 Home 的广义 PENDING 审批计数与分页不满足此口径；实施时计数、入口分页与可见任务使用同一谓词，其他审批仍从审批中心可达，旧消费者保持版本兼容。

普通进行中任务不计入前两个指标；三个数量不相加为任务总数。Home、入口分页和全部事情不得只根据当前已加载的一页计算全量数量。

2026-10-27 用户确认的指标与清单调整覆盖主设计第 3.1/3.2 节和 HOME-03 中旧“本周到期”目标，以本节 `due_soon` 为新客户端口径。清单默认以“已完成/已归档”展示同一 Workspace snapshot 中已验收的顶层 `DONE` 任务；正式 canonical Home 和旧兼容列表均支持这一分组，可打开详情。2026-10-27 后续用户反馈进一步明确：Android/Web 默认此刻页不展示“卡住的事情 / 我在推进 / TA 在推进”三段任务列表，也不显示“全部事情”快捷入口；入口下方显示“已经过期”和“已完成/已归档”同级清单，其中逾期清单默认折叠。逾期项来自同一 snapshot 中未删除、未完成且截止时间早于客户端当前时刻的顶层任务，包括 BLOCKED/REVIEW。服务端 canonical Home 分组仍保留；“全部事情”继续由“我的”进入。`CANCELLED` 仍作为已取消历史单独保留，不新增 `ARCHIVED` 任务状态。

Home 的 `week.timezone` 标签允许首版已冻结的 `Asia/Shanghai`，保留旧响应的 `UTC` 兼容；`start/end` 继续解析服务端给出的时间点，客户端不重新推算业务周或 14 天窗口。客户端不能因拒绝正式业务时区标签而丢弃整个 Home 响应。

### 2.5 全部事情查询

保留现有 `GET /api/v1/tasks` 和 `GET /api/v1/tasks/search` 的兼容路径，增加同一任务仓储支持的规范化查询参数：

```text
GET /api/v1/tasks?q=&status=&handler=&include_history=&limit=&after=
```

- `q` 覆盖标题、当前分类、负责人显示名和 `next_step_text`；服务端负责 trim、大小写/空白处理和稳定排序。
- `status=open` 表示 `TODO/IN_PROGRESS/BLOCKED/REVIEW`；另支持 `all`、`blocked`、`review`、`done`、`cancelled` 和 `handoff_pending`。`handoff_pending` 是待处理请求过滤，不是任务状态。
- 默认 `status=open`；显式 `status=all/done/cancelled` 决定历史范围，不受默认 `include_history=false` 排除。`include_history` 仅在未指定 status 时作为旧查询兼容参数；`true` 等价于 all。软删除行始终排除，组合参数优先级须有测试。
- 分页使用绑定 workspace/viewer/查询条件的 opaque keyset cursor；响应返回 `items`、`has_more`、`next_cursor` 和规范化查询摘要。
- 查询响应中的任务继续使用共享 snapshot 字段和当前状态映射；不为全部事情复制一套任务模型。

来源恢复由客户端维护：Android 使用内存中的来源视图和 `PageStorage`/任务 ID 锚点，Web 在任务详情返回时保留来源路由与筛选参数。返回不是重新打开默认此刻，也不能丢失用户草稿。

2026-10-10 实施状态补充：Web 目前先提供快照内的搜索/筛选交互，搜索覆盖标题、分类、负责人显示名和 `next_step_text`；`全部`/`未完成`/`阻塞`/`验收`/`接棒`/`完成`范围及我/TA 负责人筛选可组合使用。它尚未消费上方 keyset 查询参数，因此不代表大列表分页、服务端规范化搜索和任务详情来源状态恢复已完成。开发预览的样例数据仅存于当前页面状态，不请求 API，也不能作为正式身份或协作数据。

## 3. 辅助领域的模型边界

### 3.1 共享记账

新增独立 `ledger_entries` 领域表和模块，不复用 `tasks`、任务审批或浏览器存储。金额字段使用整数分，当前货币固定 `CNY`；收支类型、付款/收款人、记录人、创建/修改时间、版本和软删除/审计字段分开保存。月度汇总基于月份内全部有效明细，独立于支出/收入明细筛选。

写命令必须校验当前 Workspace 成员、金额大于零、日期和类别，携带幂等键/版本，并在一个事务中写账目、审计活动和 cursor。删除必须二次确认，不能映射到任务完成。API、Repository、Android/Web 页面和 PostgreSQL 约束在同一实施批次交付。

### 3.2 打卡

新增独立 `habits` 与 `habit_checkins` 领域表。习惯只有一个 `owner_id`，频率只允许 `DAILY/WEEKLY/MONTHLY`；尚未到开始日期或已暂停不得打卡；日周期键为日期、周周期键为周一日期、月周期键为年月。周期键按 Workspace 业务时区计算，数据库唯一约束保证 `(habit_id, frequency_snapshot, period_key)` 最多一条有效记录。只有本人能新增、编辑、暂停、恢复、打卡、撤销本期或删除；另一位成员只读。

打卡写入使用幂等键和数据库唯一冲突处理，保留历史周期和频率快照。暂停不删除记录，修改频率不重写历史。删除习惯需要确认并说明关联打卡记录一起删除；业务读取一并移除，审计保留，物理删除/软删除策略在领域迁移规格中明确。跨日、周、月、时区和 DST 使用注入时钟/时区测试，不能依赖测试当天。

### 3.3 纪念日与准备事项

新增独立 `anniversaries` 表，保存原始公历 `anchor_date`、类型、准备天数、备注、版本和审计信息。双方可查看和编辑，修改保留审计；类型为纪念日/生日/重要日子，准备天数为 0/1/3/7/14/30。原始日期仍在未来时首次发生就是原始日期，不提前到今年；当天显示“就是今天”。下一次日期按 Workspace 业务时区的日历日期计算；非闰年 2 月 29 日取 2 月 28 日，倒计时使用日期差而不是时间点差。

手动生成准备事项时，在 `tasks.source_key` 或独立来源约束中使用：

```text
anniversary:{anniversary_id}:{occurrence_date}
```

同一 Workspace 内该来源键唯一，双方并发生成最多一条并返回同一个任务 ID。生成者是唯一负责人，初始 `IN_PROGRESS`，截止为本次发生日期；下一步必须有明确可读文本，来源信息写入活动。生成的任务使用普通任务下一步、交接、阻塞、验收和完成闭环；删除纪念日不能删除已生成任务，修改纪念日不能悄悄改写既有任务截止日期或历史。

## 4. 同步、权限与失败边界

- 任务、账目、习惯、打卡和纪念日均通过 Workspace snapshot/changes 或明确的资源变更进入同一 cursor 流；不建立本地事实源。
- WebSocket 继续只发送最新 cursor 提示，正文仍由 REST 拉取；任何派生 Home 或辅助领域读取失败都保留 last-known-good 数据并标记 stale。
- 所有领域写请求使用稳定 request/idempotency key；涉及已有实体的请求带期望版本。超时只能使用原 key 查询或重试，不能创建第二条事实。
- 服务端从会话取得 actor、workspace 和成员关系；客户端字段、浏览器 URL、`localStorage` 和“我/TA”字符串不能决定权限或负责人。
- 未授权、状态冲突、版本冲突、校验失败、网络失败和数据过期返回可区分的稳定错误码。客户端保留表单输入、弹层和最近有效快照。
- 首先迁移任务契约和导航；辅助领域不能使用临时假数据掩盖 API/数据库未完成。

## 5. 发布和验收边界

阶段完成必须同时更新实施计划和 `docs/05-development-status.md`，写入真实命令、测试数量、环境和限制。以下事实不能用自动化测试替代：

- 授权 Android 设备安装、登录、返回、键盘、安全区、320/360/393/412 宽度和大字体检查；
- 双用户真实 Workspace 的交接、验收、记账、本人打卡和准备事项生成；
- 干净 PostgreSQL 迁移、重启持久性、备份/恢复和 cursor 继续；
- Web 窄视口、无障碍、重复提交、超时和 QR 真实授权；
- APK/AAB 的 API origin、签名、归档完整性和 checksum。

### 6.2 创建给 TA 与阻塞恢复

v1 创建自己负责的任务应直接可推进；创建给 TA 必须在同一事务创建任务（创建者负责）、唯一交接请求、活动、版本、cursor 和幂等结果，不能在客户端串联“创建成功再发交接”后留下半成品。双方有效成员和目标不是本人由服务端校验；单人起步不允许选择不存在的 TA。请求持有拟下一步，接受时与 owner 一起应用，拒绝保留原下一步且原因必填。

v1 新建映射到内部 `IN_PROGRESS`；旧客户端保留原创建状态行为，必须在兼容命令/版本中区分并测试，不能只把 TODO 文案改为进行中就认定创建语义完成。所有待处理交接/验收互斥，提交者不能自验收。解除阻塞应保持 owner；现有 `resume_handler_id` 可否指向另一成员及历史请求如何处理需单独审计与兼容测试，禁止解除时绕过交接确认改 owner。
