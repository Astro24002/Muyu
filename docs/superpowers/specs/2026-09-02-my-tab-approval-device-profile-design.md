# 我的页审批、设备管理与用户资料设计

## 1. 决策摘要

本设计调整 Android 的“我的”页和审批入口，同时明确首版设备策略：

- 审批中心是统一入口，入口固定在“我的”页 AppBar 右上角；
- 清单页“更多”不再提供任务审批入口；
- 审批中心首版只展示和处理任务审批；
- 设备验证作为未来安全增强方案保留，不在首版启用；
- 通过手机号验证码登录的设备默认是“已验证”设备；
- 用户可以撤销自己账号下的其他设备，但不能撤销当前设备；
- 用户头像继续使用现有默认头像，不引入猫头像、随机头像、图片上传或对象存储；
- 用户名称支持编辑，首版不实现头像资源编辑；
- 共享空间未匹配时显示默认头像占位和“匹配中”，匹配后显示对方真实成员信息；
- “我的”页采用个人资料、共享空间、用户概览、设备管理四个独立区域，不使用信息过密的单一账号卡片。

当前文档是 Android 本轮交互和边界的设计依据。它不改变现有两人 Workspace、任务负责人、任务审批和 Web 扫码登录协议。

## 2. 范围与非目标

### 范围

- Android 清单页菜单入口调整；
- Android “我的”页信息架构和视觉布局；
- 统一任务审批入口；
- 用户名称编辑；
- 默认头像显示；
- Workspace 匹配状态和对方头像显示；
- 设备管理入口、设备撤销和二次确认；
- 验证码登录设备的默认可信策略。

### 非目标

- 本轮不实现设备验证审批；
- 本轮不创建“设备验证任务”；
- 不把设备授权写入 `Task` 或 `TaskApprovalRequest`；
- 不增加猫头像、随机头像、头像上传、图片裁剪或对象存储；
- 不增加管理员、多人审批、跨 Workspace 审批；
- 不在 Web 端增加个人资料编辑；
- 不改变任务审批的数据库模型和状态机。

## 3. 审批入口

### 3.1 入口位置

“我的”页面 AppBar 右上角固定显示两个操作：

```text
[审批中心] [扫码登录 Web]
```

审批图标显示当前用户待处理任务审批数量；数量为零时不显示数字角标。扫码登录 Web 继续沿用现有回调和可信 Android 设备授权流程。

清单页、四象限页和日程页不显示审批入口。清单“更多”菜单只保留排序和显示设置。

### 3.2 审批中心内容

首版审批中心继续使用当前任务审批形式：

```text
审批中心
├── 待我审批
│   ├── 任务内容修改
│   ├── 四象限修改
│   ├── 状态修改
│   ├── 负责人转移
│   ├── 删除任务
│   └── 删除评论
└── 我发起的
    └── 任务审批记录
```

设备验证不出现在首版审批中心。未来启用设备验证时，可以使用相同的卡片和审批交互，但后端仍应保持设备授权实体与任务审批实体分离。

## 4. 设备策略

### 4.1 首版行为

手机号验证码校验成功后：

1. 当前 Android 设备创建或恢复为登录设备；
2. 设备状态直接为 `ACTIVE`，对外显示“已验证”；
3. 不创建设备审批请求；
4. 不要求 Workspace 另一位成员确认；
5. 设备立即拥有与账号当前权限一致的读写能力。

设备验证相关模型、签名挑战和审批任务的设计暂时保留在历史设计中，不进入本轮运行路径。

### 4.1.1 历史数据切换

策略切换时，对已有数据执行一次性兼容处理：

- 所有未撤销的 `PENDING` Android 设备转为 `ACTIVE`，并补齐 `enrolled_at`；
- 未完成的设备授权请求标记为 `CANCELLED` 或 `EXPIRED`，不再要求用户处理；
- 已撤销设备保持 `REVOKED`，不恢复其会话；
- 设备授权历史和审计记录保留，不回写任务审批记录。

这样可以保证迁移后“验证码登录即已验证”的规则对历史设备也成立。

### 4.2 设备管理

“我的”页只显示紧凑入口：

```text
设备管理                         >
```

进入后显示：

```text
设备管理

当前设备
└── 本机 Android · 已验证

其他设备
├── Android 设备 · 已验证       [删除]
└── Android 设备 · 已验证       [删除]
```

删除规则：

- 只能删除当前账号下的其他设备；
- 当前设备不显示删除按钮；
- 删除操作必须经过二次确认；
- 确认后设备状态变为 `REVOKED`，其移动会话和刷新令牌全部撤销；
- 保留设备撤销审计记录；
- 被撤销设备再次通过验证码登录时，按新设备直接创建为已验证设备；
- Web 临时会话不计入 Android 设备列表。

二次确认文案：

```text
删除登录设备

删除后，该设备将退出当前账号，需要重新通过验证码登录。

取消                         确认删除
```

## 5. “我的”页面信息架构

### 5.1 页面结构

```text
我的

AppBar： [审批中心] [扫码登录 Web]

个人资料
共享空间
用户概览
设备管理
```

四个区域使用普通页面分区，不把设备列表、审批列表和用户统计塞进同一个大型账号卡片。

### 5.2 个人资料区

```text
┌──────────────────────────────┐
│  [默认头像]                   │
│  用户名称                     │
│  脱敏手机号              编辑 │
└──────────────────────────────┘
```

头像使用当前已有默认 `CircleAvatar` 样式。首版用户资料编辑只允许修改用户名称：

- 名称首尾空格被清理；
- 空名称允许保存，页面回退显示“我的账号”；
- 名称长度由后端统一限制；
- 保存成功后更新登录会话中的用户资料并刷新页面；
- 不增加头像上传或头像选择接口。

### 5.3 共享空间区

未匹配时：

```text
共享空间
┌──────────────────────────────┐
│  [我的默认头像]  [默认头像]  │
│  我的账号          匹配中     │
│                              │
│  等待对方加入                 │
└──────────────────────────────┘
```

已匹配时：

```text
共享空间
┌──────────────────────────────┐
│  [我的头像]      [对方头像]   │
│  我的名称        对方名称     │
│                              │
│  已匹配 · 2/2 位成员          │
└──────────────────────────────┘
```

规则：

- 未匹配时占位头像不可点击；
- 未匹配时不展示虚假的对方名称、手机号或任务统计；
- 匹配后通过 Workspace bootstrap 成员数据展示对方信息；
- 对方头像点击后打开紧凑的对方概览；
- 成员状态异常时显示状态文字，不伪造已匹配结果。

成员响应继续使用现有结构，并补充或沿用默认头像标识的扩展点；本轮客户端可以继续回退到默认头像，不要求新增头像资源。

### 5.4 用户概览区

```text
我的概览

任务总数       12
未完成          4
已完成          8
延期次数        3
累计延期        2天4小时
```

统计规则保持现有设计：

- 只统计未删除任务；
- 只统计 `current_handler_id` 为目标用户的任务；
- 父任务和子任务分别计数；
- 统计所有任务，不按标签、四象限或页面筛选条件缩小范围；
- 刷新失败时保留上一次成功快照的统计结果；
- 对方概览复用同一统计模型，只替换目标用户 ID。

## 6. API 与数据变更

本轮必须新增或调整：

```http
PATCH /api/v1/me
```

请求首版只支持：

```json
{
  "display_name": "新的用户名称"
}
```

响应继续返回当前用户完整资料和当前设备状态。已有 `/me`、登录响应和 Workspace 成员响应继续兼容当前默认头像回退，不要求本轮持久化头像字段。

设备撤销接口沿用现有设备管理接口：

```http
POST /api/v1/devices/{device_id}/revoke
```

服务端必须校验：

- 设备属于当前登录账号；
- 设备不是当前会话设备；
- 设备尚未撤销；
- 操作请求通过二次确认后的客户端调用；
- 撤销设备同时撤销其移动会话。

验证码登录服务必须停止按账号设备数量创建 `PENDING` 设备；新建设备统一使用 `ACTIVE`，并直接建立可写移动会话。

## 7. 客户端组件边界

建议调整或新增：

```text
client/lib/screens/cloud_workspace_screen.dart
client/lib/screens/my_profile_screen.dart
client/lib/screens/device_management_screen.dart
client/lib/screens/task_approval_screen.dart
client/lib/profile/profile_repository.dart
client/lib/profile/profile_edit_screen.dart
```

职责：

- `CloudWorkspaceScreen`：只负责 Tab、顶部入口和页面导航；
- `MyProfileScreen`：负责四个资料区域和同步后的统计刷新；
- `DeviceManagementScreen`：负责设备列表、状态和撤销确认；
- `TaskApprovalScreen`：只负责任务审批；
- `ProfileRepository`：负责当前用户资料读取和名称更新；
- `ProfileEditScreen`：负责用户名称编辑表单。

## 8. 错误与状态处理

- 个人资料保存失败：保留输入内容并显示可重试错误；
- 共享空间加载失败：显示当前已有缓存信息，并提供重试；
- 匹配请求进行中：显示“匹配中”，不显示空白或错误成员；
- 设备撤销失败：设备列表保持原状态并提示重试；
- 撤销当前设备：服务端拒绝，客户端不提供入口；
- 审批数量刷新失败：保留上次数量，不阻塞“我的”页面；
- 无任务审批时：审批中心显示“暂无待处理审批”。

## 9. 测试与验收

### Flutter

- 清单“更多”不包含任务审批；
- “我的”右上角显示审批和 Web 扫码入口；
- 未匹配时显示默认头像占位和“匹配中”；
- 匹配后显示对方头像和名称；
- 用户名称可以编辑并保存；
- 个人资料保存失败时输入内容不丢失；
- 设备管理从“我的”跳转；
- 当前设备没有删除按钮；
- 其他设备删除需要二次确认；
- 设备撤销成功后刷新列表；
- 任务审批仍可正常查看、批准和拒绝；
- 用户概览包含父任务、子任务和延期统计。

### Backend

- 验证码登录创建的设备默认为 `ACTIVE`；
- 新增设备不产生设备审批请求；
- 当前设备不能被撤销；
- 其他设备撤销会撤销关联会话；
- 不能撤销其他账号设备；
- `PATCH /me` 只允许修改用户名称；
- 名称长度和输入格式校验稳定；
- Workspace 匹配状态和成员信息保持正确；
- 任务审批流程不受设备策略调整影响。

### 不在本轮执行

- 设备验证审批流程；
- 设备作为任务写入普通任务表；
- Android 真机验收（除非测试环境连接设备）。

## 10. 后续安全增强预留

未来如果需要提高设备安全等级，可以新增独立的设备验证审批投影：

```text
设备验证请求
  ↓
审批中心统一卡片
  ↓
另一位用户批准
  ↓
设备变为已验证
```

该功能届时仍应保留 `DeviceAuthorizationRequest` 的安全字段和签名校验，只在审批中心复用任务审批的展示形式，不应把设备记录伪装成普通任务，也不应影响现有任务统计。
